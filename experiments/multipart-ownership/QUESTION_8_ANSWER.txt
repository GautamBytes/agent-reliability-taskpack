My hardest task was a streaming upload repair in my personal Werkzeug task pack, based on real parser bugs and upstream file-cleanup work.

The first version covered fragmented uploads and exact file contents. I made the next version enforce real byte limits for each file and the whole form, even when part headers gave false sizes. It also had to handle partial writes, clean up every opened temporary file after any failure, keep the original error, and leave successful uploads open for the caller. These rules had to work through the parser and Request APIs, including repeated file names and parser reuse.

I tested gpt-6.1-sol through Codex in 16 fresh Harbor/Docker runs, 8 per version. Both used the same starting code, medium reasoning, resource limits and a 300-second solve budget. The verifier accepted 8 of 8 before and 8 of 8 after, so collected-source correctness went from 100% to 100%. Normal completion plus passing checks was 8/8 to 7/8, or 100% to 87.5%. There were 0 before and 1 after timeouts. Passing collected patches from timed-out runs are kept separate from normal completions. 

The checks grew from 100 to 171. I checked the reference, two valid alternatives and seven incomplete fixes before freezing the tasks. I kept every attempt and replayed all 16 saved patches in clean offline verifiers, including the timed-out attempt.

I published the frozen setup before testing. The repo includes every patch, individual test results, failure review and screenshots. This was a small same-model study.
