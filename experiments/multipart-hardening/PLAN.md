# Matched task-hardening experiment

Outcome: produce an honest question-8 answer with exact native coding-agent attempt counts, a concrete task change and measured before/after pass rates. No desired failure rate is a gate.

## Workflow

1. Read the Principles section of poteto-mode. Done.
2. Frame. One real Werkzeug baseline, two public task versions, separate private verifiers and references, five fresh native attempts per version.
3. Design. Basic version asks for the real 64KiB trailing-CR upload fix. Hard version requires the complete existing fragmentation contract plus valid delimiter padding, EOF closing delimiters and preservation of invalid delimiter lookalikes as payload. Same baseline source and runtime.
4. Establish baseline failures, reference passes and incomplete-fix rejection before any coding trials. Independently review the public contract and private assertions. Freeze both task trees and protocol.
5. Run ten attempts, alternating basic and hard, with the same model, reasoning, 300-second solve deadline, source revision and container resources. At most two in parallel. No private feedback or reuse of a preceding candidate.
6. Reconstruct all saved production patches, replay final verification and classify timeouts and infrastructure errors separately. Keep all ten planned attempts, including failures. No score-driven test changes or discarded failures.
7. Report exact completion and functional-patch rates, versions, per-case failures, controls and limits. Publish readable proof and a short plain-English answer if the evidence supports it.

## Verification gates

Every intended reference passes its selected preservation and private checks. Each original baseline fails its intended regression. Hard reference must also pass the basic contract. Graders remain offline with candidate imports unprivileged and protected external assertions. Public requirements must cover every private assertion. Fuzz arrangements remain subcases rather than inflated independent test counts. A valid alternative implementation cannot be rejected merely for spelling or helper choice.

## Throughput and ownership

Scaffold/reference author owns version instructions, environment metadata and solution patches. Verifier author owns private tests, exact case manifests, worker extensions and verifier counts. Coordinator owns protocol, job scheduling, aggregate evidence and publishing. Each run gets a distinct output tree/container; no candidate source or private feedback is shared across attempts.

The protocol will be frozen after reference and fairness review, before the first counted trial. This is a small same-model study, not a statistical or contamination-free difficulty claim. A pass-rate drop is an observation to explain, not a target to manufacture.
